# Stitch Redesign Master Plan

## 목적
- Google Stitch 시안을 기준 디자인 레퍼런스로 채택한다.
- 기존 기능/상태/라우팅/가드 로직은 유지한다.
- 사용자 경험만 엔터프라이즈 수준으로 재정비한다.

## 리디자인 원칙
1. 기능은 유지하고 표현만 바꾼다.
2. 랜딩 -> 진단 -> 결과 -> 추천 -> 신청 -> 이력 -> 챗봇 흐름을 하나의 제품처럼 보이게 만든다.
3. Stitch 시안의 정보 위계, 카드 구조, 스텝 진행 표현은 적극 채택한다.
4. 현재 코드의 인증/권한/스테이지 가드는 그대로 유지한다.
5. 개발 중 임시 문구, 잠금 안내, 프로토타입 티 나는 요소는 제거 또는 축소한다.

## 기준 시안
- 홈: `stitch/home_dashboard`
- 진단: `stitch/competency_diagnosis_quiz`
- 결과: `stitch/diagnosis_results_analysis`
- 추천: `stitch/course_recommendations`
- 과정상세/신청: `stitch/course_detail_application`
- 이력: `stitch/learning_growth_dashboard`
- 챗봇: `stitch/ai_learning_assistant_chat`
- 관리자 참고: `stitch/admin_analytics_dashboard`
- 디자인 토큰 참고: `stitch/design_system_guideline`

## 채택 결정
### 그대로 채택
- 상단 브랜드 바 + 명확한 CTA 버튼 구조
- 단계형 여정 진행 표시
- 큰 KPI 카드와 보조 지표 카드 조합
- 결과 리포트의 점수 카드 + 강점/보완 역량 분리
- 추천 카드에서 추천 근거를 짧은 문장으로 노출하는 방식
- 우측 보조 패널을 활용한 도움말/지원센터/팁 영역

### 수정 후 채택
- 추천 카드 썸네일 비중은 축소한다.
- 관리자 대시보드의 글로벌 SaaS 느낌은 유지하되 일반 사용자 화면과 브랜드 톤을 맞춘다.
- 챗봇의 장식성보다 실사용성 중심으로 여백/정보 밀도를 조정한다.
- 이력 화면의 잠금 문구는 실제 상태 기반 행동 유도로 대체한다.

### 제외 또는 축소
- 과도한 플레이스홀더 이미지
- "다음 단계 잠금" 같은 반복적인 프로토타입 문구
- 실제 데이터 없이 과하게 풍부해 보이는 가짜 분석 블록

## 제품 공통 디자인 기준
### 톤
- 신뢰감 있는 한국 대기업 학습 플랫폼
- 밝은 배경, 진한 네이비, 선명한 블루 포인트
- 운영 도구 같은 안정감 + AI 서비스다운 정교함

### 레이아웃
- 데스크톱 우선 12-column
- 본문 최대폭은 넓게 가져가되 카드 그룹은 명확히 분리
- 페이지 공통 상단에 현재 단계, 목적, 다음 액션이 보이게 구성

### 컴포넌트
- KPI 카드
- 단계 진행 바
- 상태 배지
- 추천 근거 칩
- 요약 패널
- Empty/Error/Loading 공통 패턴

### 마이크로카피
- 한국어 기준으로 정리
- "추천 이유", "다음 학습", "신청 연동", "최근 진단 결과" 같은 업무 언어 사용
- 시스템 상태는 짧고 단정하게 표현

## 페이지별 리디자인 목표
### Home
- Stitch 홈을 기준으로 제품 첫인상을 고정한다.
- 진단 시작, 이전 결과 보기, 현재 점수, 추천 과정 수를 첫 화면에서 확인 가능하게 한다.
- 공지/학습 소식과 지원센터 영역은 유지하되 과밀하지 않게 정리한다.

### Diagnosis
- 질문 카드와 하단 고정 액션 구조를 Stitch안처럼 정돈한다.
- 진행률, 남은 단계, 임시 저장 상태를 명확히 보여준다.
- 문항 타입별 인터랙션 일관성을 확보한다.

### Result
- 현재 진단 결과 영역을 Stitch 결과 리포트 구조로 재편한다.
- 종합 점수, 스킬맵, 강점/보완 역량, 해석 가이드를 한 페이지에서 완결한다.
- 추천 이동 CTA를 최상단과 하단에 모두 둔다.

### Recommendation
- 현재 기능을 유지하면서 Stitch 추천 카드형 레이아웃으로 재구성한다.
- 필터/정렬/추천 근거를 상단에서 이해 가능하게 만든다.
- 카드당 액션은 `상세보기`와 `수강 신청`으로 단순화한다.

### Course Linking
- 과정 상세 정보, 학습 목표, 커리큘럼, 신청 연동 버튼의 우선순위를 높인다.
- 외부 이캠퍼스 이동임을 명확히 안내하되 전환 마찰은 낮춘다.

### History
- 성장 타임라인, 수료 과정, 평균 학습 시간, 집중 강화 역량을 구조적으로 재배치한다.
- 표와 카드가 한 제품 안에서 자연스럽게 이어지도록 정리한다.

### Chatbot
- 좌측 요약/로드맵, 중앙 대화, 우측 팁 패널의 3분할 구조를 기준으로 삼는다.
- 추천 이유와 다음 행동 유도 버튼을 더 실제 서비스답게 정리한다.

### Responsive
- Stitch 데스크톱 레이아웃을 기준으로 모바일과 태블릿에 맞는 축소 규칙을 정의한다.
- 카드, 표, 하단 액션 바의 반응형 우선순위를 문서화한다.

## 워크트리 하달 기준
### foundation
- 공통 레이아웃, 상단 바, 단계 진행 구조, 공통 카드/버튼/배지

### diagnosis
- 진단 화면과 결과 화면의 구조 재정비

### recommendation
- 추천 목록 카드, 필터, 추천 근거 표현

### course-linking
- 과정 상세/신청 연동 페이지 재구성

### history
- 성장 대시보드와 학습 이력 시각 정리

### chatbot
- 챗봇 3열 레이아웃과 빠른 질문 UX 정리

### responsive
- 전 페이지 반응형 규칙과 QA 완료

## 통합 품질 게이트
1. 모든 페이지는 공통 브랜드 바와 공통 토큰을 사용한다.
2. CTA 이름은 흐름 전체에서 일관적이어야 한다.
3. 진단 결과와 추천 근거의 연결이 시각적으로 드러나야 한다.
4. 로딩/빈 상태/오류 상태가 디자인 시스템 안에서 통일되어야 한다.
5. 관리자 화면은 일반 사용자용 경험과 섞지 않고 확장 슬롯으로 유지한다.

## 이번 웨이브 산출물
- 워크트리별 리디자인 작업지시서
- 페이지별 채택/수정/제외 기준
- 통합 머지 순서: `foundation -> diagnosis -> recommendation -> course-linking -> history -> chatbot -> responsive`
