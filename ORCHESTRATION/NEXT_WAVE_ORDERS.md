# Next Wave Orders (Commercialization Wave 3)

## 목적
이미 연결된 `진단 -> 추천 -> 신청 -> 성장 추적` 흐름을
상용 서비스 수준으로 끌어올리기 위해,
이번 웨이브는 "설명 가능성", "운영 전환성", "반복 사용성"을 강화한다.

## 이번 웨이브의 공통 성공 기준
1. 사용자가 홈으로 재진입했을 때 현재 여정을 5초 안에 이해할 수 있다.
2. 추천 화면에서 "왜 이 과정이 추천되었는지"를 읽고 바로 신청 여부를 결정할 수 있다.
3. 신청 이후에도 성장 추적과 재진단 루프가 자연스럽게 이어진다.
4. 운영자는 부서별 드롭오프 원인과 우선 액션을 화면에서 바로 해석할 수 있다.

## foundation
- 홈 대시보드의 "이어가기" 경험 강화
- 저장한 과정 카드에 공통 액션 규칙 정의 (`이어서 보기`, `삭제`, `바로 신청`)
- 공통 상태 배지 체계 확정 (`1순위 보완`, `난이도 적합`, `추천 근거`, `운영 상태`)
- Empty / Error / Loading / Guard 상태 문구를 실제 서비스 톤으로 정리
- 릴리즈 배너, 버전 표기, 환경 토글 노출 위치 정리

## diagnosis
- 제조업 직무 맥락별 문항군 확장안 설계
- 문항별 체류 시간, 중도 이탈, 임시 저장 복귀 이벤트 정의
- 결과 화면에서 `강점`, `보완`, `즉시 추천 이유`가 한 화면에서 보이도록 재배치
- 재진단 전후 변화 비교에 쓰일 결과 스냅샷 필드 정리

## recommendation
- 추천 근거 설명 모달 또는 인라인 패널 확정
- 카드별 `난이도 적합성`, `업무 효과`, `우선순위` 설명력 강화
- 저장/비교/신청 전환 흐름을 한 리스트에서 끝낼 수 있게 액션 구조 정리
- 10개 추천 세트의 산식 요약과 역량별 분포 설명 UX 구체화

## course-linking
- 이캠퍼스 외부 이동 파라미터 운영안 정리
- 신청 성공/실패/복귀 누락 상태 정의
- 신청 직전 설득 영역(학습효과, 예상 일정, 추천 근거) 강화
- 신청 후 개인 학습 플랜과 캘린더를 이력 페이지와 연결하는 계약 정리

## history
- 재진단 전후 성장 변화 카드 고도화
- 부서/직무별 벤치마크와 드롭오프 전환율을 한 해석 흐름으로 연결
- 관리자용 액션 제안 카드의 우선순위 규칙 정의
- 월간 리포트 다운로드 요구사항 정리 (`PDF`, `CSV`)

## chatbot
- 현재 진단/추천/선택 과정 상태를 반영한 컨텍스트 답변 가이드 고도화
- 빠른 질문과 실제 추천 결과를 더 촘촘하게 연결
- 상담 종료 시 다음 액션을 홈/추천/이력으로 유도하는 기준 정리
- 운영용 FAQ와 사용자용 상담 톤을 분리할 수 있는 초안 작성

## responsive
- 1440 / 1280 / 1024 / 768 / 430 / 390 기준 반응형 QA
- 저장 카드, 비교 패널, 학습 캘린더, 관리자 그리드 축소 규칙 정리
- 키보드 포커스, 스크린리더 라벨, 색 대비 점검 완료
- 긴 테이블/타임라인/챗봇 패널의 모바일 우선순위 규칙 문서화

## 선행 의존성
1. foundation의 공통 배지/카드/상태 패턴 확정
2. diagnosis의 결과 스냅샷 필드 확정
3. recommendation과 course-linking의 신청 상태 계약 일치
4. history와 chatbot의 요약 데이터 소스 일치

## 릴리즈 위험요소
1. 이캠퍼스 실제 파라미터가 아직 운영 확정되지 않으면 신청 연동은 데모 수준에 머문다.
2. 진단 이력과 추천 이력의 저장 정책이 서버 기준과 다르면 성장 추적이 어긋날 수 있다.
3. 관리자 지표는 데모 데이터를 넘어 실제 API 계약이 필요하다.
