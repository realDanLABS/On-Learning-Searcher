# Wave 3 Sprint Backlog

## 목적
상용화 방향의 개발 항목을
"바로 착수 가능한 작업" 단위로 쪼개서
워크트리별 병렬 진행이 가능하도록 만든 백로그.

## Sprint Goal
- 사용자가 홈에서 현재 상태를 이해하고
- 추천 이유를 납득한 뒤
- 신청 후 성장 추적까지 끊김 없이 이어지는 경험을 완성한다.

## P0

### foundation
1. 홈 저장 과정 카드 액션 규칙 확정
- 산출물: 액션 우선순위 표 (`이어서 보기`, `삭제`, `바로 신청`)
- 완료 기준: recommendation / history에서도 동일 의미 재사용 가능

2. 홈 "현재 단계 / 다음 액션 / 최근 변화" 위계 재배치
- 산출물: 화면 구조 초안
- 완료 기준: 5초 내 현재 상태 파악 가능

3. 공통 상태 패턴 정리
- 산출물: Empty / Error / Guard / Loading 카피 가이드
- 완료 기준: 핵심 페이지에 공통 적용 가능

### diagnosis
1. 결과 스냅샷 계약 정식화
- 산출물: `resultSnapshotId`, `strengthAreas`, `recommendedFocusSummary` 포함 계약서
- 완료 기준: recommendation / history / chatbot 공용 사용 가능

2. 진단 중도 이탈 이벤트 설계
- 산출물: 이벤트 정의서 (`questionIndex`, `elapsedMs`, `savedDraft`)
- 완료 기준: 운영 지표로 전환 가능

3. 결과 리포트 위계 정리
- 산출물: 강점 / 보완 / 추천 이유 / CTA 구조안
- 완료 기준: 한 화면에서 핵심 해석 가능

### recommendation
1. 추천 이유 패널 확정
- 산출물: 인라인 패널 또는 모달 결정안
- 완료 기준: 카드 단독 설명력 부족 문제 해소

2. 카드 액션 우선순위 정리
- 산출물: 저장 / 비교 / 신청 액션 규칙
- 완료 기준: 충돌 없이 1차 CTA가 분명함

3. 추천 산식 요약 정리
- 산출물: 10개 추천 구성 원리 설명안
- 완료 기준: 사용자/운영자 모두 설명 가능

### course-linking
1. 신청 상태 정의
- 산출물: `requested`, `enrolled`, `failed`, `return-missing` 의미표
- 완료 기준: history / chatbot와 동일 해석

2. 외부 이동 파라미터 문서화
- 산출물: 이캠퍼스 파라미터 표
- 완료 기준: 운영팀 검토 가능 수준

3. 신청 직전 설득 영역 정리
- 산출물: 추천 근거 / 학습효과 / 일정 요약 구조안
- 완료 기준: 신청 이탈 포인트 감소 방향 설명 가능

## P1

### history
1. 재진단 전후 변화 카드 고도화
2. 부서/직무 벤치마크와 전환율 흐름 연결
3. 액션 제안 카드 우선순위 규칙 문서화
4. 월간 리포트 다운로드 요구사항 정리

### chatbot
1. 상태 기반 답변 매트릭스 정리
2. 빠른 질문과 실제 추천 데이터 연결 규칙 정리
3. 상담 종료 후 다음 액션 유도 규칙 정리
4. 운영 FAQ / 사용자 상담 톤 분리

## P2

### responsive
1. 저장 카드 / 비교 패널 / 관리자 그리드 반응형 체크리스트
2. 모바일 축소 규칙 문서화
3. 접근성 QA (포커스, ARIA, 색 대비)

## Sprint Exit Criteria
- P0 항목이 모두 체크인 문서에 반영된다.
- `foundation + diagnosis` 결과를 바탕으로 `recommendation + course-linking`이 착수 가능해진다.
- 릴리즈 리스크 중 "계약 미정" 상태가 최소 2개 이상 해결된다.
