# Commercialization Checklist

## 목적
온러닝서처를 데모 수준이 아니라
실제 사내 서비스 론칭 직전 품질로 끌어올리기 위한 점검표.

## A. 사용자 여정
- [ ] 홈에서 현재 단계 / 다음 액션 / 저장 과정 / 최근 변화가 동시에 보인다.
- [ ] 진단 시작부터 결과 확인까지 중간 이탈 없이 진행 가능하다.
- [ ] 결과 화면에서 강점 / 보완 / 추천 이유가 한 화면에서 이해된다.
- [ ] 추천 10개에 대해 우선순위 / 난이도 적합성 / 기대 업무효과가 모두 보인다.
- [ ] 추천 화면에서 저장 / 비교 / 신청 액션이 서로 충돌하지 않는다.
- [ ] 신청 화면에서 과정 상세, 추천 근거, 학습 계획, 일정이 함께 보인다.
- [ ] 신청 후 상태가 history와 chatbot에 같은 의미로 반영된다.
- [ ] 재진단 전후 성장 비교가 실제로 보인다.

## B. 데이터 / 상태 계약
- [ ] diagnosis -> recommendation payload가 최신 역량 체계와 일치한다.
- [ ] recommendation -> course-linking payload가 설명형 필드를 포함한다.
- [ ] course-linking -> history 상태에 `requested`, `enrolled`, `failed`, `return-missing`가 정의되어 있다.
- [ ] 홈 / history / chatbot이 같은 `nextRecommendedAction` 의미를 공유한다.
- [ ] 즐겨찾기 / 저장 과정 정책이 로그아웃 / 초기화 규칙과 충돌하지 않는다.

## C. 운영 / 관리자
- [ ] 부서별 벤치마크가 화면에서 해석 가능하다.
- [ ] 드롭오프 원인 가설과 액션 제안이 연결되어 있다.
- [ ] 관리자 화면에서 추천 -> 신청 전환율을 읽을 수 있다.
- [ ] 월간 리포트 요구사항 (`PDF`, `CSV`)이 문서화되어 있다.

## D. 외부 연동
- [ ] 이캠퍼스 딥링크 파라미터가 운영 기준으로 확정되어 있다.
- [ ] 신청 성공 / 실패 / 복귀 누락 상태 처리 기준이 문서화되어 있다.
- [ ] remote mode / SSO callback smoke test 계획이 있다.

## E. 품질
- [ ] `build`, `lint`, `test`가 메인 기준 통과한다.
- [ ] 1440 / 1280 / 1024 / 768 / 430 / 390 반응형 QA가 완료되었다.
- [ ] 키보드 포커스 / ARIA / 색 대비 점검이 완료되었다.
- [ ] Empty / Error / Guard / Loading 상태 문구가 제품 톤으로 정리되었다.

## F. 릴리즈 게이트
- [ ] Feature Gate: 랜딩 -> 진단 -> 추천 -> 신청 -> 이력 -> 챗봇 흐름이 모두 연결된다.
- [ ] Quality Gate: 수동 시나리오 + 회귀 테스트가 통과한다.
- [ ] Demo Gate: 끊김 없는 시연 1회 성공.
- [ ] Operations Gate: 운영 리스크(연동/저장정책/권한정책) 대응안이 문서화되어 있다.
